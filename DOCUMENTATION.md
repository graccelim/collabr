## 1. What is collabr.

### Plain English

collabr. is a two-sided marketplace connecting content creators directly with brands for paid and barter collaborations. A brand posts a campaign brief describing what content they need. Creators browse open campaigns and apply with a pitch and optional rate. The brand reviews applicants, selects one or more, and pays via an escrow system - funds are held until the brand confirms the creator's live post is up, at which point funds are automatically released to the creator.

The platform eliminates the need for PR agencies or talent management intermediaries. Brands pay a 12% platform commission (8% on the Pro plan). Creators receive their payout directly.

### Who the two user types are

**Brands** - Singapore-based businesses, typically SMEs. They post campaigns, review applicants, pay via escrow, review content drafts, and confirm live posts to release payment. Plans: `free` or `pro`.

**Creators** - Singapore-based nano and micro influencers (1k–200k followers) on Instagram, TikTok, and YouTube. They apply to campaigns, submit content drafts (file upload or link), post live, submit their post URL to trigger payment, and leave reviews.

There is also an **admin** role for platform staff to manage disputes.

### Problem solved

Traditional influencer marketing requires brands to either engage expensive PR agencies ($2,000+/month) or manage creator relationships manually with no payment protection. collabr. provides:
- Verified creator stats (follower counts)
- Structured content review workflow (48h auto-approve safety net)
- Stripe escrow protecting both sides
- Two-way ratings surfacing quality creators and responsible brands
- Direct file upload for draft submissions (videos up to 500 MB, images up to 20 MB)

### Market

Singapore, targeting local SMEs and nano/micro creators. All amounts are in SGD cents (integers). In beta - free to use while establishing the creator and brand base.

### Route groups

- `(auth)` - login, signup, forgot-password, reset-password. No sidebar. Accessible without a session.
- `(dashboard)` - all dashboard pages. Protected by the layout via `requireAuth` + redirect to `/login`. Role-specific sidebar rendered server-side.

### Supabase client usage

| Where | Client | Why |
|---|---|---|
| Server components, API routes | `createClient()` from `lib/supabase/server.ts` | Cookie passthrough for session |
| Admin operations (cron, signup) | `createAdminClient()` from `lib/supabase/server.ts` | Service role bypasses RLS |
| Client components | `createClient()` from `lib/supabase/client.ts` | Browser client |

### Middleware

`middleware.ts` runs on **every request** (except static assets and images). It:
1. Creates a Supabase server client and calls `getUser()` - this refreshes the session token and writes updated cookies back on every response.
2. Checks if the requested path starts with any protected prefix.
3. Redirects unauthenticated users to `/login?next=<pathname>`.

Protected prefixes: `/dashboard`, `/collabs`, `/campaigns`, `/jobs`, `/profile`, `/earnings`, `/boost`, `/billing`, `/notifications`, `/settings`, `/applications`, `/creators`, `/post-job`, `/admin`.

The `/forgot-password` and `/reset-password` routes are **not** in the protected list - they are intentionally public.

**Collab status machine:**

```
briefed
  → (brand pays escrow) → briefed (with stripe_payment_intent_id set)
  → (creator submits draft) → draft_submitted
      → (brand approves) → draft_approved
      → (brand requests revision, max 2) → in_revision → draft_submitted (re-submit)
      → (48h elapses, no brand action) → draft_approved [cron]
  → (creator posts live + submits URL) → live_submitted
      → (brand confirms) → completed [Stripe capture]
      → (72h elapses, no brand action) → completed [cron, Stripe capture]
  → (either party raises dispute) → disputed
      → (admin resolves) → completed or cancelled [Stripe capture or cancel]
  → (either party cancels, if in briefed/draft_submitted/in_revision) → cancelled [Stripe cancel]
```

**RLS**: `collab_parties` - full access if the user is either the creator or the brand on the collab.

## 4. User Flows

### Flow 1: Creator signup (minimal signup + onboarding checklist, 2026-07)

1. Creator visits `/signup?role=creator`
2. Selects "I'm a creator", enters ONLY name/email/password + terms
3. `POST /api/auth/signup` - creates `auth.users` row, then (via admin client) inserts `users` and a BARE `creator_profiles` row (`onboarding_completed_at` stays NULL)
4. Page flips to an in-place "Check your inbox" state (resend button included; no bounce to /login)
5. Creator clicks the Supabase verification link → `/auth/confirm` verifies the token, SETS THE SESSION COOKIE, sends the welcome email, and redirects into the app (`?welcome=1`)
6. Dashboard shows the onboarding checklist with Step 1 (Account created) pre-checked: socials → niches → photo/bio → ready. Steps are DERIVED from profile data (`lib/onboarding-steps.ts`), so progress persists and resumes anywhere
7. Adding a social via `/onboarding` (`POST /api/onboarding/creator`) sets `onboarding_completed_at` → unlocks applying. Niches/photo/bio remain optional polish

### Flow 2: Brand signup

Same shape: minimal signup → verify → checklist. The brand gate step is company details (`/onboarding` → `POST /api/onboarding/brand` sets `onboarding_completed_at`, unlocking campaign creation); then logo/description, then "post your first campaign" as the activation step.

> **Supabase config (manual, one-time)**: the *Confirm signup* email template must point its redirect at the app, not the login page:
> `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=signup&next=/dashboard`
> `/auth/confirm` already logs the user in via cookie; middleware additionally bounces any signed-in visitor from `/login` or `/signup` to `/dashboard`, so an outdated template still lands correctly.

Existing accounts (created under the long-form signup) all have `onboarding_completed_at` set, so they never see the checklist.

### Flow 3: Forgot password

1. User clicks "Forgot password?" on `/login` (link inline with the Password label)
2. Redirected to `/forgot-password`
3. Enters email → calls `supabase.auth.resetPasswordForEmail(email, { redirectTo: origin + '/reset-password' })`
4. Supabase emails a magic link; page shows "Check your email" confirmation
5. User clicks link in email → lands on `/reset-password` (Supabase sets a short-lived session from the URL hash)
6. Enters new password + confirm → `supabase.auth.updateUser({ password })`
7. Redirected to `/dashboard` on success

### Flow 4: Brand posts campaign

1. Brand visits `/post-job`
2. Fills in: title, brief, deliverable types, compensation (paid/barter/both), budget, barter detail, niche tags, min followers, creators needed, deadline
3. `POST /api/campaigns` - inserts campaign with `status: 'active'`
4. Redirected to `/campaigns`

### Flow 5: Creator applies

1. Creator browses `/jobs` (active campaigns)
2. Opens campaign detail `/jobs/[id]`
3. Sees escrow notice if campaign is paid or both
4. Fills in pitch (min 30 chars) and optional rate → `POST /api/applications`
5. `is_boosted` is copied from creator's active boost status at apply time
6. Page refreshes to show "Application submitted" state

### Flow 6: Brand selects creator

1. Brand opens campaign `/campaigns/[id]`
2. Sees stat cards: Total / Pending / Shortlisted / Selected applicant counts
3. Boosted applications appear first; free plan shows only first 5
4. Brand clicks Shortlist, Select, or Pass on each applicant
5. On Select → `PATCH /api/applications/[id]` with `status: 'selected'`
6. API creates a `collabs` row with `computeFee()` to set `platform_fee` and `creator_payout`
7. Response includes `collab_id` - client redirects to `/collabs/[collab_id]`
8. Notification sent to creator: "You've been selected for [campaign]"

### Flow 7: Brand pays escrow

1. Brand opens `/collabs/[id]` - status is `briefed`
2. If creator has no `stripe_connect_id`: warning shown, payment button hidden
3. If creator has Connect: `StripePaymentButton` mounts (Apple Pay / Google Pay)
4. On click → `POST /api/payments/create-intent` creates PaymentIntent with `capture_method: 'manual'`
5. Brand completes Apple Pay / Google Pay in browser
6. Funds held in Stripe escrow (`requires_capture` state)
7. Page refreshes to "Escrow active" state

### Flow 8: Draft submission workflow

1. Creator opens `/collabs/[id]` - status is `briefed`, `in_revision`, or `draft_approved`
2. `DraftSubmitForm` appears with two tabs: **Upload file** and **Paste a link**
3. **Upload file path**:
   - Creator selects file (MP4/MOV ≤500 MB or JPG/PNG ≤20 MB)
   - Client uploads to `draft-submissions` bucket at `{collab_id}/{timestamp}_{filename}`
   - On success, calls `createSignedUrl(path, 3600)` to get a 1-hour signed URL
   - Submits to `POST /api/collabs/[id]/submit-draft` with `file_url` + optional `creator_note`
4. **Paste link path**: creator pastes Google Drive / Dropbox / WeTransfer URL, submits directly
5. API increments version, inserts `submissions` row, sets collab status to `draft_submitted`, sets `draft_auto_approve_at` to 48h from now
6. Brand notified by in-app notification + email
7. **Brand reviews** via `POST /api/collabs/[id]/review-draft`:
   - `approved` → status → `draft_approved`; creator notified; email sent
   - `revision` (max 2) → status → `in_revision`; creator notified with feedback
   - `rejected` → status stays `draft_submitted`; creator can dispute
8. If brand does **not** respond within 48h → cron auto-approves

### Flow 9: Live post submission

1. Creator opens `/collabs/[id]` - status is `draft_approved`
2. Creator submits live URL via `CollabActions` (not yet surfaced as a form in the current UI - submit-live action needs to be wired to a UI element)
3. `POST /api/collabs/[id]/submit-live` creates `live_posts` row, sets status to `live_submitted`, sets `live_auto_release_at` to 72h from now
4. Brand notified by in-app notification + email

### Flow 10: Brand confirms live post + payment release

1. Brand opens `/collabs/[id]` - sees "Confirm & release payment" button when status is `live_submitted`
2. Clicks → `POST /api/collabs/[id]/confirm-live`
3. API captures the Stripe PaymentIntent
4. `live_posts.confirmed_at` set; collab status → `completed`
5. Creator's `collabs_completed` and `total_earned` incremented
6. Creator notified by in-app notification + email with payout amount
7. If brand doesn't act within 72h → cron auto-releases

### Flow 11: Star rating (after completion)

1. Both brand and creator see `ReviewForm` on `/collabs/[id]` when status is `completed`
2. Hover over 5 stars, click to select, write optional note, click "Submit review"
3. `POST /api/reviews` inserts a review row
4. Page refreshes; form replaced by read-only stars
5. Nightly cron recalculates `creator_profiles.rating_avg` and `rating_count` from all brand reviews

### Flow 12: Dispute

1. Either party on a collab clicks dispute (in `briefed`, `draft_submitted`, `in_revision`, or `live_submitted` status)
2. `POST /api/collabs/[id]/dispute` with `reason` (min 20 chars) and optional `evidence_urls`
3. Collab status → `disputed`; both parties notified + emailed
4. Admin visits `/admin/disputes`, opens dispute detail
5. Admin submits resolution via `DisputeResolutionForm` → `POST /api/disputes/[id]/resolve`
6. Outcome options: `creator_wins` (capture full), `brand_wins` (cancel), `split` (partial capture), `mutual` (cancel)
7. Both parties notified with outcome label

### Flow 13: Creator Boost

1. Creator visits `/boost`
2. Chooses S$4 (7 days, per_app) or S$20/mo (30 days, monthly)
3. `POST /api/payments/boost-creator` with `type` field
4. In beta: no Stripe payment - boost activated immediately
5. `boost_active_until` set on `creator_profiles`
6. On next application, `is_boosted` is copied to the application row
7. Boosted applications sorted to top of brand's applicant list
8. Nightly cron `expire-boosts` nullifies expired `boost_active_until` values

### Flow 14: Creator payout setup

1. Creator visits `/earnings` - sees Stripe Connect banner
2. Clicks "Set up payouts with Stripe" → `POST /api/stripe/connect`
3. API creates Stripe Express account (SG, transfers capability) and account link
4. Creator completes Stripe onboarding
5. Redirected back to `/earnings?connect=complete` - "Payouts active" banner shown
6. `stripe_connect_id` saved to `creator_profiles`

## 5. Payment Architecture

### Escrow flow (Stripe manual capture)

```
Brand pays
    → POST /api/payments/create-intent
    → stripe.paymentIntents.create({ capture_method: 'manual', currency: 'sgd' })
    → funds held in Stripe (requires_capture)

Brand confirms live post
    → POST /api/collabs/[id]/confirm-live
    → stripe.paymentIntents.capture(intentId)
    → funds released to Stripe platform account

[Stripe Connect payout to creator happens separately via Connect transfer - future work]
```

### Commission calculation (`lib/utils.ts`)

```typescript
function computeFee(rateCents: number, plan: 'free' | 'pro') {
  const pct = plan === 'pro' ? 0.08 : 0.12
  const fee = Math.round(rateCents * pct)
  return { fee, payout: rateCents - fee }
}
```

- Free plan: 12% fee
- Pro plan: 8% fee
- All amounts in SGD cents (integers)
- `platform_fee` + `creator_payout` = `agreed_rate`

### Payment display (`lib/utils.ts`)

```typescript
function formatSGD(cents: number): string {
  return `S$${(cents / 100).toFixed(2)}`
}
```

### Stripe Connect (creator payouts)

- Express accounts (SG), transfers capability
- `creator_profiles.stripe_connect_id` stores the account ID
- Account created lazily on first onboarding click
- Brand's `stripe_customer_id` created lazily on first payment
- Actual transfer to creator via Connect transfer not yet implemented (funds captured to platform account)

### Stripe webhook events handled

| Event | Action |
|---|---|
| `payment_intent.succeeded` | Records `stripe_payment_intent_id` on collab if not already set |
| `payment_intent.payment_failed` | Logs error; collab stays in `briefed` - brand can retry |
| `account.updated` | Confirms Connect account when `details_submitted = true` |

Webhook endpoint: `POST /api/webhooks/stripe`
Secret: `STRIPE_WEBHOOK_SECRET` env var

### Apple Pay / Google Pay (`StripePaymentButton.tsx`)

- Uses Stripe.js `PaymentRequest` API
- Checks `canMakePayment()` - shows fallback text if not available
- Renders native browser payment UI (wallet button)
- Country: `SG`, currency: `sgd`

## 8. API Routes

All routes return JSON. Auth check: `supabase.auth.getUser()`. Errors return `{ error: string }` with HTTP status.

### Auth

#### `POST /api/auth/signup`

Body: `{ email, password, name, role: 'brand'|'creator' }` — nothing else; socials/niches/company details are collected post-verification by the onboarding checklist.

Creates `auth.users`, `users`, and a bare role-specific profile via admin client (`onboarding_completed_at` NULL). Rate-limited 5/hour/IP; enumeration-safe duplicate handling (409). Welcome email is sent from `/auth/confirm` when the link is clicked (or immediately if email confirmation is disabled). Returns `{ success: true, requiresEmailVerification }`.

#### `POST /api/auth/signout`

Called by sidebar "Sign out" form. Supabase handles session destruction.

---

### Campaigns

#### `POST /api/campaigns`

Brand only. Body: all campaign fields. Creates campaign with `status: 'active'`. Returns new campaign row.

#### `PATCH /api/campaigns/[id]`

Brand only (owner). Body: partial campaign fields. Updates campaign.

---

### Applications

#### `POST /api/applications`

Creator only. Body: `{ campaign_id, pitch, proposed_rate? }`. Checks not already applied. Sets `is_boosted` from creator's current boost status. Returns new application row.

#### `PATCH /api/applications/[id]`

Brand only (campaign owner). Body: `{ status: 'shortlisted'|'selected'|'rejected' }`.

On `selected`: creates `collabs` row with `computeFee()`, sends notification to creator.

Response: `{ success: true, status, collab_id? }` - `collab_id` is included when status is `selected`.

---

### Collabs

#### `POST /api/collabs/[id]/submit-draft`

Creator only (collab owner). Body: `{ file_url, creator_note? }`.

Requires status in `briefed | in_revision | draft_approved`. Auto-increments version. Sets `draft_auto_approve_at` = now + 48h. Sends notification + email to brand.

Response: `{ success: true, auto_approve_at }`.

#### `POST /api/collabs/[id]/review-draft`

Brand only (collab owner). Body: `{ decision: 'approved'|'revision'|'rejected', feedback? }`.

Requires status `draft_submitted`. Revision requires feedback ≥20 chars; max 2 revisions total. Updates submission record and collab status. Sends notification + email to creator.

Response: `{ success: true, decision }`.

#### `POST /api/collabs/[id]/submit-live`

Creator only (collab owner). Body: `{ post_url, screenshot_url? }`.

Requires status `draft_approved`. Creates `live_posts` row. Sets `live_auto_release_at` = now + 72h. Sends notification + email to brand.

Response: `{ success: true, auto_release_at }`.

#### `POST /api/collabs/[id]/confirm-live`

Brand only (collab owner). Requires status `live_submitted`.

Captures Stripe PaymentIntent. Marks `live_posts.confirmed_at`. Sets collab status to `completed`. Increments creator's `collabs_completed` + `total_earned`. Sends notification + email to creator.

Response: `{ success: true }`.

#### `POST /api/collabs/[id]/dispute`

Either party. Body: `{ reason, evidence_urls? }`.

Requires status in `live_submitted | draft_submitted | in_revision | draft_approved`. Sets collab to `disputed`. Creates `disputes` row. Notifies and emails both parties.

Response: `{ success: true }`.

#### `POST /api/collabs/[id]/cancel`

Either party. Requires status in `briefed | draft_submitted | in_revision`.

Cancels Stripe PaymentIntent if present. Sets collab to `cancelled`. Notifies the other party.

Response: `{ success: true }`.

---

### Payments

#### `POST /api/payments/create-intent`

Brand only. Body: `{ collab_id }`.

Creates or retrieves Stripe PaymentIntent with `capture_method: 'manual'`, SGD, for `agreed_rate` cents. Creates Stripe customer for brand if none exists. Saves `stripe_payment_intent_id` on collab.

Response: `{ client_secret }`.

## 10. Background Jobs (Cron)

Crons are defined in `vercel.json` and run on Vercel's cron infrastructure (requires Pro plan for <1 day intervals). Each job is a GET route handler authenticated with `Authorization: Bearer {CRON_SECRET}`.

| Job | Schedule | Route |
|---|---|---|
| Auto-approve drafts | 9:00 AM daily | `/api/cron/auto-approve-drafts` |
| Auto-release live payments | 10:00 AM daily | `/api/cron/auto-release-live` |
| Notify expiring windows | 8:00 AM daily | `/api/cron/notify-expiring` |
| Expire boosts | Midnight daily | `/api/cron/expire-boosts` |
| Update creator ratings | 2:00 AM daily | `/api/cron/update-ratings` |

### `auto-approve-drafts` (9:00 AM daily)

Finds all collabs in `draft_submitted` where `draft_auto_approve_at < now`. For each:
- Sets status → `draft_approved`, clears `draft_auto_approve_at`
- Sets all pending submissions to `approved`
- Notifies creator ("Draft auto-approved - post live now!")
- Notifies brand ("You did not review within 48h")

### `auto-release-live` (10:00 AM daily)

Finds all collabs in `live_submitted` where `live_auto_release_at < now`. For each:
- Captures Stripe PaymentIntent (non-fatal if Stripe fails)
- Sets `live_posts.confirmed_at` = now
- Sets collab status → `completed`
- Increments creator's `collabs_completed` + `total_earned`
- Notifies and emails creator with payout amount

### `notify-expiring` (8:00 AM daily)

Sends reminders to brands:
- Drafts auto-approving within 6h: notification per brand
- Live payments auto-releasing within 12h: notification per brand

### `expire-boosts` (Midnight daily)

Finds all `creator_profiles` where `boost_active_until < now` and sets `boost_active_until = null`.

### `update-ratings` (2:00 AM daily)

Reads all brand reviews (reviewer_type = 'brand'). Groups by creator. Computes average rating and count per creator. Updates `creator_profiles.rating_avg` and `rating_count`.

## 11. Business Rules

1. **All monetary values are SGD cents (integers).** Never store floats. Multiply by 100 on input, divide by 100 for display.

2. **Commission rates**: Free plan = 12%, Pro plan = 8%. `platform_fee + creator_payout = agreed_rate`.

3. **Free plan limits**: First 5 applicants visible; remaining hidden behind upgrade prompt. Future: max 2 active campaigns.

4. **Boosted applications sort first** in applicant lists: `ORDER BY is_boosted DESC, created_at ASC`.

5. **Draft auto-approve**: If brand does not act on a submitted draft within 48 hours, it auto-approves.

6. **Live auto-release**: If brand does not confirm a live post within 72 hours, payment auto-releases.

7. **Maximum 2 revision rounds** per collab. Third revision would be a scope change requiring explicit creator agreement.

8. **Revision feedback minimum 20 characters** - must be specific and actionable.

9. **Dispute reason minimum 20 characters**.

10. **Unique application**: A creator cannot apply to the same campaign twice (DB unique constraint on `(campaign_id, creator_id)`).

11. **Unique review per side**: One review per collab per reviewer type (DB unique constraint on `(collab_id, reviewer_type)`).

12. **Dispute can only be raised** when collab is in `draft_submitted`, `in_revision`, `draft_approved`, or `live_submitted`.

13. **Cancel can only be done** when collab is in `briefed`, `draft_submitted`, or `in_revision`.

14. **Payment capture is idempotent**: Stripe's API is called only if intent status is `requires_capture`. If already captured, no duplicate charge.

15. **Escrow funds held in Stripe** with `capture_method: 'manual'`. Transfer to creator's Connect account is a future feature - currently captured to platform account.

16. **Draft file upload**: Private `draft-submissions` bucket. Accepted types: MP4/MOV (≤500 MB), JPG/PNG (≤20 MB). Path format: `{collab_id}/{timestamp}_{filename}`. Access via signed URL (1-hour expiry).

17. **Logo upload**: Public `brand-assets` bucket. Accepted types: PNG, JPG, WebP (≤2 MB). Path format: `logos/{user_id}-{timestamp}.{ext}`.

18. **Session refresh on every request**: Middleware calls `supabase.auth.getUser()` unconditionally to refresh the session token and write updated cookies back. This prevents session expiry mid-session.

19. **Forgot password flow**: Uses Supabase's `resetPasswordForEmail` with `redirectTo: /reset-password`. The reset page uses `updateUser({ password })`. No separate backend route needed.

20. **Cron secret**: All cron jobs check `Authorization: Bearer {CRON_SECRET}` header and return 401 if missing or wrong. CRON_SECRET is set in Vercel environment variables.

11. **Admin stats page** - `/api/admin/stats` route exists but the admin UI for platform statistics is not built.

12. **Dispute evidence upload** - the schema has `evidence_urls text[]` and the API accepts it, but there is no file upload UI on the dispute form.

### Low priority / future

13. **Push notifications** - in-app only for now; no web push or mobile push.

14. **Campaign analytics** - no metrics beyond applicant counts shown to brands.

15. **Creator portfolio links** - not yet a profile field; creators can mention in bio.
